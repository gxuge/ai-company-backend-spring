# Skill 标题与描述编写规范

Skill 的标题和描述用于帮助模型准确判断是否应加载或委托该能力。

## 标题

- 使用简洁、明确的中文业务名称。
- 直接描述能力，例如“角色创建”“角色形象生成”。
- 不使用代码名、`skill`、`agent`、`preset`、`full` 等实现术语。
- frontmatter 的 `name` 与正文一级标题保持一致。

## 描述

描述应依次说明：

1. 能做什么：明确处理内容和最终产出。
2. 何时使用：列出常见用户表达和触发场景。
3. 信息不足时如何处理：说明是否仍应使用并通过对话补全。
4. 何时不使用：写清与相近 Skill 的职责边界。

推荐格式：

```text
通过……完成……。用户提出……时使用；即使……也应使用。不用于……。
```

## 示例

不推荐：

```yaml
name: role_create_image
description: 根据已有数据直接生成图片。
```

推荐：

```yaml
name: 角色形象生成
description: 通过自然对话收集或补全角色的外貌、服装和气质，并生成角色形象图片。用户提出创建角色形象、人物立绘、头像或全身像时使用；即使缺少详细外观信息也应使用。不用于创建完整角色设定。
```

## 同步要求

调整 Skill 标题或描述时，同时检查对应节点、子 Agent 定义和主 Agent 可见的路由描述，确保触发条件与职责边界一致。
