## 任务分解

### T1 统一模型与策略
- 输入：审核类别、分数和动作要求。
- 执行动作：新增请求、结果、枚举和分数策略。
- 输出：稳定的 `ModerationService` 契约。
- 验收标准：八类风险和三种动作均可表达。
- 证据类型：单元测试、代码 diff。

### T2 审核实现与 Adapter
- 输入：现有 `IAIChatHandler` 和 AIRAG 模型 ID。
- 执行动作：使用独立审核 Prompt 调用线上模型，并由 Adapter 转换 JSON。
- 输出：可替换的 `ModerationService` 实现。
- 验收标准：不明确结果会携带最近上下文复审一次；异常失败关闭。
- 证据类型：单元测试。

### T3 文本流程接入
- 输入：`LlmNode`、Prompt Chat、普通聊天。
- 执行动作：主 LLM 前输入审核，生成后输出审核，中风险重写复审。
- 输出：统一输入输出安全门禁。
- 验收标准：输入非 `ALLOW` 不调用主模型；输出非安全不直接返回。
- 证据类型：交互测试、Mockito 调用次数。

### T4 图片 Prompt 与日志
- 输入：图片文本 Prompt 和审核结果。
- 执行动作：生成图片前审核 Prompt；记录脱敏审核日志。
- 输出：图片 Prompt 门禁和结构化日志。
- 验收标准：图片风险 Prompt 不调用图片供应商；日志无完整正文。
- 证据类型：单元测试、日志字段检查。
