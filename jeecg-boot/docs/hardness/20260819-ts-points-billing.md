- 分级：H3

- 关联需求：用户提供的积分/星钻体系需求

## 目标与非目标
- 目标：所有积分变化通过统一服务完成，余额与流水处于同一事务。
- 目标：消费、充值、退款和会员赠送支持幂等，积分余额永不为负。
- 目标：提供用户视角与平台视角账单，并返回机器可识别错误码。
- 非目标：不重构会员等级、会员权益和会员订单对外契约。
- 非目标：不实现前端页面和会员订单退款。

## 输入约束
- 已知上下文：会员支付通过 `PaymentServiceImpl` 调用
  `ITsMemberService.activateVerifiedPayment` 完成结算。
- 强约束：`sys_user.id`、会员表用户 ID 均为 `VARCHAR(32)`。
- 强约束：统一响应继续使用 `Result<T>`。
- 强约束：写操作使用 `@Transactional(rollbackFor = Exception.class)`。
- 禁止事项：业务代码直接更新积分余额；删除或覆盖历史积分流水。

## 任务分解

### T1 积分核心账本
- 输入：积分账户、流水和内部业务接口需求。
- 执行动作：新增模型、Mapper、Service、Controller、原子 SQL 和积分异常。
- 输出：账户查询、流水查询、增加、消费、退款、后台调整。
- 验收标准：余额与流水同事务；余额不足返回 `POINTS_NOT_ENOUGH`；
  重复幂等 Key 不重复记账。
- 证据类型：单元测试、Mapper XML、模块编译。

### T2 积分充值
- 输入：现有 `PaymentProvider` 和积分商品需求。
- 执行动作：新增积分商品、充值订单、支付流水和回调结算。
- 输出：创建充值支付、查询订单、Stripe/PayPal 回调和后台充值列表。
- 验收标准：金额/币种/支付意图一致；成功回调只发放一次积分。
- 证据类型：服务测试、SQL 索引、模块编译。

### T3 双视角统一账单
- 输入：会员订单、积分充值订单和积分流水。
- 执行动作：新增用户账单、平台账单、详情和平台汇总查询。
- 输出：用户与平台独立 Controller/VO，钱和积分方向分别表达。
- 验收标准：分页稳定；用户接口只能读取本人数据；充值不重复展示。
- 证据类型：Mapper XML、权限检查、查询测试。

### T4 会员赠送积分衔接
- 输入：已验签会员支付成功编排。
- 执行动作：在会员结算成功后按积分规则执行幂等赠送。
- 输出：`MEMBER_GIFT` 积分流水。
- 验收标准：重复支付回调不重复发放；未配置规则不影响会员开通。
- 证据类型：服务测试、日志与代码审查。

## 风险与回退
- 风险：两类支付流水共享 webhook，路由判断错误会导致订单无法结算。
- 风险：跨源账单查询的状态映射不一致。
- 风险：数据库迁移先后顺序错误导致运行期缺表。
- 回退：回退新增代码并逆序删除积分表；会员原有表和接口保持不变。
