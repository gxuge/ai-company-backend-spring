## 目标与非目标
- 目标：新增 `impression` 白名单事件并严格校验三个归因字段。
- 目标：故事卡片满足 50% 可见、连续 500ms 后批量上报并按请求去重。
- 目标：保持业务接口和页面交互不受埋点失败影响。
- 非目标：不计算正负样本，不采集停留时长，不接入形象档案卡片。

## 输入约束
- 已知上下文：`/sys/ts-events/collect/batch` 已支持最多 100 条事件。
- 强约束：用户 ID 来自登录态；事件仅写 Kafka/ClickHouse；属性值为 64 字以内非空文本。
- 禁止事项：不得修改 ClickHouse 表结构，不得用形象档案 ID 冒充角色 ID，不得改变页面布局。

## 任务分解
### T1 后端事件契约
- 输入：现有九类事件白名单和统一属性校验。
- 执行动作：增加 `impression`，校验角色/故事资源以及 `scene/requestId/position`，位置必须为正整数。
- 输出：枚举、服务校验、单元测试。
- 验收标准：合法曝光可发布，缺字段或非法位置被拒绝。
- 证据类型：定向单元测试结果。

### T2 前端批量上报
- 输入：现有单条业务行为 API。
- 执行动作：增加事件构建、曝光队列、定时批量刷新和静默失败。
- 输出：`ts-behavior.ts`。
- 验收标准：单批不超过 20 条，未登录不入队，失败不影响页面。
- 证据类型：Babel Web 转译。

### T3 页面可见性接入
- 输入：故事发现页 ScrollView 和三列 StoryGrid。
- 执行动作：记录卡片内容坐标与视口，达到阈值后按请求去重上报。
- 输出：发现页和 StoryGrid。
- 验收标准：同一请求同一故事最多一条；搜索、分类、切换后生成新请求 ID。
- 证据类型：代码检查和目标文件转译。

### T4 文档与回归
- 输入：API、ADR、架构、计划和变更记录。
- 执行动作：同步十类事件和曝光例外说明。
- 输出：前后端文档。
- 验收标准：文档口径与实现一致。
- 证据类型：文本扫描和编码检查。
