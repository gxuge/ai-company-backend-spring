## 目标与非目标
- 目标：统一奖励事件、幂等状态和策略分发，现有接口契约变化数量为 0。
- 目标：签到和任务奖励保持同事务，会员奖励只在支付事务提交后触发。
- 目标：积分余额直接更新入口数量为 0，全部通过 `ITsPointsService`。
- 目标：提供管理员事件分页、汇总、详情和失败重试，页面不允许修改奖励金额。
- 非目标：本轮不迁移现有规则表、不新增统一规则编辑接口、不用 AOP 计算奖励。

## 输入约束
- 已知上下文：`TsActivityServiceImpl`、`TsRewardServiceImpl`、`PaymentServiceImpl`、`TsMemberPointsGiftServiceImpl`。
- 强约束：`POINTS_NOT_ENOUGH` 等积分机器错误码保持不变；重复事件不得重复入账。
- 禁止事项：禁止修改现有 Controller 契约，禁止直接更新积分余额。

## 任务分解
### T1 数据模型
- 输入：现有活动奖励记录和积分流水。
- 执行动作：新增奖励事件迁移、Entity、Mapper、枚举、DTO 和 VO。
- 输出：`reward_event` 及持久化模型。
- 验收标准：`event_id` 唯一，状态、重试次数、错误码和结果可追踪。
- 证据类型：SQL、源码、编译结果。

### T2 事件执行
- 输入：活动奖励服务和会员赠送服务。
- 执行动作：实现协调器、执行器、分发器和两类处理器。
- 输出：统一事件入口。
- 验收标准：同一 `event_id` 重复执行只返回原结果；未知事件返回机器错误码。
- 证据类型：单元测试、源码。

### T3 链路接入
- 输入：签到、任务领取和支付成功逻辑。
- 执行动作：活动改为同步事件；支付改为提交后事件。
- 输出：业务接口无感接入。
- 验收标准：活动事务失败不保留半成品奖励；支付事务未提交不触发会员赠送。
- 证据类型：测试、diff、编译结果。

### T4 验证与文档
- 输入：事件中心和管理端需求。
- 执行动作：新增后台接口、Vue3 页面、菜单，再执行定向测试、编译、差异和编码检查。
- 输出：可查询和重试的后台页面、验证证据及变更记录。
- 验收标准：页面可筛选、查看详情和受控重试；模块编译成功，无新增空白错误。
- 证据类型：命令输出、文档。

## 风险与回退
- 风险：支付后事件失败造成会员已开通、赠送积分延迟。
- 触发条件：`reward_event.status=FAILED`。
- 回退步骤：恢复支付内直接调用；积分幂等键继续防止重复发放；按迁移末尾语句删除事件表。
- 回退验证：重复支付回调不重复开通会员，重复奖励请求不重复积分入账。
