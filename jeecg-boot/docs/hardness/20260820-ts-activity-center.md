## 目标与非目标
- 目标：提供用户、管理员和内部行为三组 `ts` 前缀接口。
- 目标：所有星钻奖励经 `ITsRewardService -> ITsPointsService` 发放并生成流水。
- 目标：签到、行为上报和任务领取重复请求不重复发奖或累计。
- 非目标：不修改会员、会员权益和积分接口契约；本期不实现 ITEM/TITLE/AVATAR_FRAME 发放器。

## 输入约束
- 写接口参数必须通过 JSON Body 传递，禁止将业务 ID 放在路径中。
- 用户数据必须从登录态取用户 ID；内部接口要求 `ts:activity:internal`。
- 每日、每周任务必须按周期隔离进度。

## 任务分解
### T1 数据模型
- 执行动作：建立任务、进度、签到、奖励、加成规则和行为去重表。
- 验收标准：唯一索引覆盖签到、周期进度、奖励与行为幂等。
- 证据类型：迁移脚本与 XML 校验。

### T2 活动与奖励服务
- 执行动作：实现周期进度、签到、领取和会员加成，统一调用积分服务。
- 验收标准：不直接更新积分账户；重复调用只返回原结果。
- 证据类型：服务单元测试与代码审查。

### T3 接口与查询
- 执行动作：实现用户、后台、内部接口及分页查询。
- 验收标准：无路径业务参数；用户查询有归属过滤；分页稳定排序。
- 证据类型：路由扫描、Mapper XML、模块编译。
