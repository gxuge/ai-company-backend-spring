# ADR 0017：统一 AI 文本审核流程

## 状态
已采纳

## 背景
全局安全 Prompt 能约束模型行为，但不能替代模型调用前后的独立审核。Agent、TS Prompt、普通聊天和图片 Prompt 使用不同调用入口，若各入口直接解析厂商审核结果，会造成字段、阈值和失败策略不一致。

## 决策
- 在 AIRAG 模块新增统一 `ModerationService`，业务入口只依赖统一请求和 `ModerationResult`。
- 第一版审核实现使用独立审核 Prompt 调用线上 AIRAG 文本模型，由 Adapter 将 JSON 响应转换为统一字段。
- Java 风险策略根据分数生成 `ALLOW`、`SAFE_REPLY`、`BLOCK`，不直接采用模型返回动作。
- 审核结果不明确时，追加当前消息和最近上下文复审一次。
- 输入非 `ALLOW` 时不调用主模型；输出中风险安全重写一次并再次审核，高风险或复审失败返回固定安全回复。
- Agent 输出先在服务端缓冲，完成输出审核后再通过 SSE 发送。
- 审核日志只记录元数据、长度和 SHA-256 摘要前缀，不记录完整内容。

## 结果
- 厂商字段与聊天主流程隔离，后续自部署模型可通过替换 `ModerationService` 实现接入。
- 所有目标文本入口共享相同风险动作和失败关闭语义。
- Agent 流式首字延迟增加，但避免未审核内容提前到达用户。

## 非目标
- 不审核图片像素。
- 不新增审核日志数据库表。
- 不修改现有业务 API 返回结构。
