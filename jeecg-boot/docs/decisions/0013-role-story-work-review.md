# ADR-0013：角色与故事使用独立作品审核域

## 状态
已采纳，2026-08-23。

## 背景
角色、故事及其图片属于可版本化作品；反馈和评论属于社区互动内容；角色/故事公开记录则负责渠道、排序和上下架。三者的生命周期、审核对象和回滚方式不同。

## 决策
- 新建 `ts_work_review`、`ts_work_review_item`、`ts_work_review_log`，不复用反馈评论审核表。
- 作品保存后由后端从正式记录重建 JSON 快照并计算 SHA-256，审核只针对固定版本。
- 流程固定为 `PENDING_AI -> PENDING_ADMIN -> APPROVED/REJECTED`；内容更新后旧任务转 `OBSOLETE`。
- 作品审核决定“当前版本能否公开”，公开记录继续负责渠道配置和上下架，两套状态同时满足才能被游客访问。
- AI 调用异常保持 `PENDING_AI`，不得失败放行；管理员可触发重试。

## 图片边界
- 图片 URL 作为独立 `IMAGE` 审核项固化，管理员详情可查看固定地址。
- 当前 AI 适配器复用文本 Tool Call 模型，向模型提供图片正式 URL 和作品上下文；若模型不能可靠读取图片，应返回 `MANUAL`。
- 后续接入专用图片安全供应商时，只替换 AI 审核适配能力，不改变作品任务、快照和管理员终审模型。

## 结果
- 作品审核、社区内容审核、公开运营互不污染。
- 任意内容编辑都会触发新版本，旧审核结论不能误用于新内容。
- 历史有效作品迁移为 `APPROVED`，避免升级时整体下架。

## 回滚
先停止新审核写入并导出审核历史，再回退 Java/XML；删除三张审核表和 Prompt，最后移除角色、故事的四个审核字段与公开查询过滤。
