# ADR-0022 内容标签生成与版本生命周期

## 背景
旧 `ts_tag_type/ts_tag` 服务于生成提示词素材，未参与角色和故事业务。新的标签用于描述已生成或已保存的内容，并需要与内容版本保持一致。

## 决策
- 保留 `ts_tag_type/ts_tag` 表名，将其语义改为固定内容标签词典。
- AI 生成接口可选返回候选标签，保存时由后端统一校验后写入。
- 内容标签存入 `ts_content_tag`，以 `content_type + content_id + tag_id` 唯一。
- 每次写入携带 `content_version`；旧版本异步任务不得覆盖新版本。
- 作品审核快照提交后创建独立打标任务；当前版本已有标签时直接跳过。
- 打标任务使用独立有界线程池，失败只更新任务状态，不影响作品审核。

## 取舍
- 生成时携带标签可减少模型调用，但 Prompt 尚未返回标签或用户手动编辑时仍需兜底。
- 复用审核快照避免重复拼装角色、故事字段，并天然提供版本与内容哈希。
- 不把候选标签写入角色或故事 `ext_json`，避免形成第二份不可约束的数据源。

## 影响与回滚
- 旧生成素材标签数据被替换，相关管理接口字段同步调整。
- 回滚时恢复旧标签表备份，并删除新增内容标签和任务表。
