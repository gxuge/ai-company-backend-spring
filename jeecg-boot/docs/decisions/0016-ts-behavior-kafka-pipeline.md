# ADR 0016：推荐行为采用 Kafka 双消费者链路

## 状态
已接受，2026-08-23。

## 背景
访问、曝光、点击和互动事件需要用于推荐模型离线训练与在线特征更新，同时不能让主业务请求同步承担明细入库和特征计算成本。

## 决策
- 登录用户通过统一单条/批量接口上报行为。
- Controller 与 Service 仅校验、补充可信用户 ID，并异步发送 Kafka。
- MySQL 明细消费者和 Redis 特征消费者使用不同消费者组，独立消费同一 Topic。
- MySQL 使用 `event_id` 唯一索引去重；Redis 使用短期事件去重键后更新用户特征。
- Kafka 未启用时拒绝采集请求，避免返回虚假的接收成功。

## 影响
- 主业务请求不直接写行为明细和实时特征。
- 第一阶段 MySQL 适合低至中等数据量；增长后可将明细消费者替换为 ClickHouse 或数据湖。
- Redis 特征属于可重建数据，不作为行为事实来源。

## 回滚
关闭行为 Kafka 功能开关，回退新增接口、生产消费代码和配置；删除新增明细表不会影响现有浏览历史数据。
