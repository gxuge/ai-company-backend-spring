# ADR 0012：反馈内容审核状态与计数策略

## 状态
已接受

## 背景
反馈中心已有 `status=received/processing/completed` 表示业务处理进度。反馈、
评论/回复和追加内容目前发布后立即公开，缺少内容审核和审核历史。

## 决策
- 新增独立 `audit_status=pending/approved/rejected`，不复用业务处理状态。
- 用户发布的反馈、评论/回复和追加内容默认待审核；官方回复默认通过。
- 作者可查看自己的未通过内容，其他用户只能查看审核通过内容。
- 点赞、评论和回复只能作用于审核通过目标。
- `comment_count` 只统计审核通过的评论与回复，在审核状态进入或离开
  `approved` 时原子增减。
- 审核通过和驳回写入 `ts_feedback_audit_log`，记录目标、前后状态、原因和审核人。
- 管理端使用统一队列，以 `feedback/comment/append` 区分审核目标。

## 影响
- 部署前必须先执行审核字段和日志表迁移。
- 前端“我的反馈”可展示 `auditStatus/auditReason/auditedAt`。
- 管理端需要使用 `feedback:admin:audit` 权限访问审核接口。

## 备选方案
- 复用反馈业务状态：会混淆内容合规与问题处理进度，拒绝采用。
- 评论发布即增加计数、审核时只控制展示：公开计数会包含不可见内容，拒绝采用。

## 回滚
回退应用代码后，删除审核日志表、审核索引和三张内容表的审核字段。历史反馈、
评论和追加内容本身不受影响。
