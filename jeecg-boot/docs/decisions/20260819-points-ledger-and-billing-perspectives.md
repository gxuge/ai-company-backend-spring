# ADR：积分账本与双视角统一账单

## 状态
- 已采纳
- 日期：2026-08-19

## 背景
- 现有会员订单和支付流水已经稳定运行，不应为积分体系重构会员核心模型。
- 积分充值同时产生现金支出和积分收入，单一 `direction` 无法完整表达。
- 积分消费、退款和支付回调必须在并发与重复请求下保持余额和流水一致。

## 决策
- 积分使用独立账户和只追加流水，所有余额变化统一经过
  `ITsPointsService`。
- 账户行锁作为同一用户记账串行点；锁定后检查幂等 Key，再执行带余额
  条件的原子更新并插入流水。
- 积分充值使用独立订单和支付流水，但复用 Stripe/PayPal
  `PaymentProvider`。
- 支付 webhook 先匹配会员支付流水，未匹配时再匹配积分充值支付流水。
- 账单分别提供用户视角和平台视角接口，返回 `moneyDirection` 与
  `pointsDirection`。
- 充值订单作为复合账单，不重复展示其关联的 `RECHARGE` 积分流水。
- 积分业务异常通过 `Result.errorCode` 返回机器错误码，余额不足固定为
  `POINTS_NOT_ENOUGH`。

## 影响
- 新增五张积分业务表和一张会员积分赠送规则表。
- 会员 Controller、会员订单结构和会员权益接口保持不变。
- `PaymentServiceImpl` 增加积分充值回调路由和会员赠送积分编排。
- 前端应按 `errorCode` 判断余额不足，不应解析中文错误消息。

## 备选方案
- 扩展现有 `payment_transaction` 增加订单类型：会改变既有会员支付语义，
  本次不采用。
- 使用一个账单接口传入 `perspective`：容易出现权限和方向解释混淆，
  本次拆成用户和平台接口。
- 在 Java 内存合并三类账单后分页：无法保证稳定分页和筛选性能，本次使用
  Mapper XML `UNION ALL`。

## 回滚
- 回退积分相关 Java、XML 和文档。
- 移除 `PaymentServiceImpl` 的积分充值路由和会员积分赠送调用。
- 按迁移脚本注释中的逆序语句删除积分表；既有会员数据不受影响。
