# ADR：业务事实埋点替代旧推荐权重埋点

## 状态
已接受，2026-08-29。

## 背景
旧模型允许任意事件并在 Redis 中计算通用推荐权重，但当前产品只需要少量可解释的业务事实，且 ClickHouse 已作为分析数据源接入。

## 决策
- 事件目录固定为十类业务事实，新增受约束的推荐曝光 `impression`。
- 创建、收藏、连接、聊天和生图由后端成功结果产生。
- 语言、详情浏览和推荐曝光由登录后的前端上报。
- Kafka 继续承担异步解耦，明细消费者改写 ClickHouse。
- 删除停留时长、任意曝光字段、匿名 ID、标签和旧 Redis 权重；曝光仅保留
  `scene/requestId/position` 三个归因字段。
- 旧 MySQL 明细表保留但停止写入，不做破坏性删除。

## 影响
- 新数据口径更稳定，可直接按事件、资源、语言、性别和风格聚合。
- 推荐曝光可与后续详情、收藏、连接和聊天事实关联，形成候选正负样本。
- 旧客户端事件将被事件白名单拒绝，需要前后端同步发布。
- ClickHouse 初始化脚本必须随部署包交付。

## 回滚
关闭 `TS_BEHAVIOR_KAFKA_ENABLED`；回退消费者和前端上报代码。ClickHouse 表可独立删除，MySQL 业务不受影响。
