# ADR：活动奖励与周期进度

## 背景
活动中心需要接入现有会员与积分体系，并支持每日、每周、长期任务以及重复消息投递。

## 决策
- 活动奖励统一经过 `ITsRewardService`，星钻奖励继续调用 `ITsPointsService.add()`。
- 每日和每周进度使用 `cycle_key` 生成独立记录，长期任务固定使用 `LONG`。
- 行为上报使用 `(user_id, condition_type, biz_id)` 唯一索引去重。
- 签到、领取和积分入账共享事务；积分幂等 Key 与活动奖励幂等 Key 保持一致。
- 现有 `FREE/PRO/ULTRA` 映射为活动域 `NORMAL/VIP/SVIP`，不修改会员接口。
- 本期仅执行 `STAR_DIAMOND`；其他奖励类型保留模型与分发边界，未实现时拒绝发放。

## 影响
- 新增六张活动表和三组 `ts` 前缀接口。
- 不修改既有会员、会员权益和积分接口。
- 活动任务配置必须先配置签到任务，用户才能执行签到。
