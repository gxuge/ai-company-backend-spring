# ADR：活动任务自动与手动发奖模式

## 背景
活动任务当前在进度完成后保持未领取状态，用户必须调用领取接口才能获得星钻。
日常和周常任务需要支持完成后自动到账，同时保留部分运营任务的手动领取体验。

## 决策
- 活动任务新增 `reward_claim_mode`，支持 `AUTO` 和 `MANUAL`，默认 `MANUAL`。
- 自动任务首次完成后将奖励状态标记为 `GRANTING`，并在业务事务提交后发布统一奖励事件。
- 奖励事件继续使用“用户 + 任务 + 周期”幂等键，避免并发或重试导致重复发奖。
- 奖励处理成功后统一将用户任务进度更新为 `CLAIMED`。
- 自动发奖失败由现有奖励事件定时任务重试，不回滚已经完成的任务进度。
- 手动任务继续通过 `/sys/ts-activity/task/receive` 领取。

## 影响
- 活动任务管理接口新增 `rewardClaimMode` 字段。
- 用户任务响应新增 `rewardClaimMode`，奖励状态可能短暂出现 `GRANTING`。
- 旧任务迁移后默认为 `MANUAL`，不改变既有行为。

## 回退
- 将自动任务的 `reward_claim_mode` 改为 `MANUAL`，恢复手动领取。
- 如需回滚字段，先确保没有 `AUTO` 任务，再删除 `reward_claim_mode` 列。
