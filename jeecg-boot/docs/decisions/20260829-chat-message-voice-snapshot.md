# 聊天消息音色快照与流式 TTS

## 状态
- 日期：2026-08-29
- 状态：已采纳

## 背景
多角色会话播放频率高，若每次 TTS 都查询活动角色和音色，会产生重复查询，并可能因角色后续换音色导致历史消息播放结果变化。

## 决策
- 生成角色消息时写入 `senderId`，并在 `contentJson.voiceSnapshot` 固化 provider 音色及参数。
- `message-tts` 只读取消息快照，不接收前端音色选择，也不查询角色表兜底。
- 同一接口通过 `stream` 区分统一 JSON 和 `audio/mpeg` 流式响应。
- Web 支持 MediaSource 时渐进播放，不支持时使用原非流式路径。

## 影响
- 新消息播放不再产生角色或音色档案查询。
- 角色后续修改音色不会改变已生成消息的声音。
- 旧消息缺少快照时无法 TTS，按产品要求不迁移、不补写。
- 不新增数据库字段，快照沿用消息 `content_json`。

## 回退
前端停止传 `stream=true` 即可回到 JSON 播放；消息快照字段可保留，不影响旧接口解析。
