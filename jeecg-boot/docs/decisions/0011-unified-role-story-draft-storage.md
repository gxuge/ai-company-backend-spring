# ADR 0011：角色与故事统一草稿存储

## 状态
Accepted

## 日期
2026-07-30

## 背景
- 角色和故事草稿都属于用户页面状态快照。
- 使用正式业务表状态模拟草稿会提前创建或修改正式数据。
- 草稿箱只需要按类型、名称和更新时间查询，并在继续编辑时恢复完整内容。

## 备选方案
1. 分别建立角色草稿表和故事草稿表。
2. 继续复用角色、故事正式表的状态字段。
3. 建立统一草稿表，使用类型字段与 JSON 快照区分业务。

## 决策
最终选择方案 3：使用 `ts_draft`，通过 `draft_type=role/story` 区分类型，通过 `content_json` 保存完整页面快照。

## 影响
- 正向影响：统一草稿 CRUD；不污染正式业务数据；后续新增草稿类型无需新增整套接口。
- 负向影响：草稿内部字段不能直接使用普通列高效筛选。
- 缓解措施：可查询字段独立保存为 `draft_type/draft_name/source_id/updated_at`，列表不读取大 JSON。

## 回滚与迁移
- 触发条件：草稿需要大量内部字段检索或 JSON 快照无法满足版本兼容。
- 回滚步骤：拆分专用草稿表和接口，迁移 `content_json` 后删除统一表。
- 兼容性影响：当前草稿表与正式角色、故事表无外键，不影响正式数据。
