# ADR-0017 后端业务行为使用注解与 AOP 采集

## 状态
已接受

## 背景
推荐行为除前端访问埋点外，还需要采集点赞、收藏、评论、发布和生成等后端已确认成功的可信事件。若在每个 Service 中直接拼装 Kafka 消息，会重复事务判断、异常隔离和字段转换逻辑。

## 决策
- 新增方法级行为埋点注解，通过 SpEL 从参数和返回值提取用户、资源和条件。
- 切面仅在业务方法成功返回后构造事件；事务存在时注册 `afterCommit`，无事务时立即发布。
- 发布协调器统一检查功能开关并吞掉埋点异常，保证推荐采集不影响核心业务。
- 事件扩展属性统一记录后端来源和业务方法名。
- 复杂或无法通过参数/返回值表达的场景继续允许手动调用协调器。

## 取舍
- 优点：业务方法只声明事件语义，事务与 Kafka 细节集中管理，后续新增关注等事件只需增加注解。
- 缺点：SpEL 属于运行时解析，字段重构无法完全依靠编译器发现，因此必须有切面测试和告警日志。
- 未选择 Controller AOP：Controller 成功返回不等于业务事务已提交，且无法稳定识别实际落库结果。

## 影响
- Kafka 开关保持默认关闭；关闭时不会连接或发送业务埋点。
- 不改变现有 Controller、DTO、数据库结构和响应格式。
- 回退时移除注解及切面组件即可，业务 Service 主体逻辑不受影响。
